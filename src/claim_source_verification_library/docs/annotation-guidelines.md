# Scope

AI-generated content has increased the need for reliable ways to evaluate the evidence behind claims in Wikipedia articles. This project builds a dataset of Wikipedia claims paired with their cited sources, annotated according to how well each source supports its associated claim. 

The dataset is intended to support the development and evaluation of automated systems for identifying insufficiently supported claims, including those appearing in AI-generated content.

## What are you doing?

You are assessing how well a cited source supports a claim.

| **component**       | **Definition**                                                                    |
| ------------------- | --------------------------------------------------------------------------------- |
| Unit of annotation  | One claim paired with one cited source                                            |
| Evidence to examine | The relevant passage (source)s and surrounding context needed to assess the claim |
| Central question    | Does the cited source provide sufficient evidence for this claim?                 |

## What are we not doing?

- Independently fact-checking the claim against other sources.
- Evaluating the credibility, reputation, or overall quality of the cited source.
- Comparing the cited source with alternative sources.
- Determining whether the claim was written by a human or generated by AI.

**Annotation principle:** Judge each claim–source pair using the evidence available in the cited source. Do not assume that a claim is supported because it sounds plausible, that a source supports it because the source is reputable, or that a claim is AI-generated simply because its citation does not support it.

Every annotator contributing to or building on this dataset should follow the same six steps:

1. **Read the claim in context.** Read the full Wikipedia sentence and, if needed, the surrounding paragraph. Identify the assertion being evaluated.
2. **Identify the cited source.** Open the citation, confirm it leads to the intended source, and record its title, URL, type, and accessibility.
3. **Locate the evidence.** Read the source, identify passages connected to the claim, and record each excerpt and its location.
4. **Compare evidence with claim.** Check whether the source establishes the claim’s material details: dates, quantities, populations, causal relationships, and degree of certainty.
5. **Assign a verdict.** Apply the predefined verdict rules, not intuition or the claim’s plausibility.
6. **Document the decision.** Record the verdict, failure type (if applicable), and a brief rationale.

## Understanding how to give a verdict

| **verdict**         | **Assign when**                                                                                                            | **Example**                                                                                                                                                |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| supported           | The source provides evidence for all the important parts of the claim.                                                     | **Claim:** The programme began in 2015. ** Source:** States the programme began in 2015.                                                           |
| Partially supported | The source provides evidence for some parts of the claim but not others, or supports a less specific version of the claim. | **Claim: **The programme began in 2015 and reached 12 states by 2018. **Source: **Gives the start year but not the expansion timeline. |
| Not supported       | The inspected source provides no evidence for the claim, or provides evidence that contradicts it.                         | **Claim:** The programme began in 2015.  **Source:** Discusses the programme but gives no start date.                                                   |
| Unable to evaluate  | The annotator cannot access enough information to determine whether the source supports the claim.                         | The cited source is inaccessible. The cited source is bloomberg article, and you don’t have an active subscription.                                     |

## Edge cases and how to give a verdict

- If the source supports the date but not the statistic, is the verdict Partially supported?
- If the source directly contradicts one component of the claim, can the verdict be Partially supported?
- If a source is paywalled, can an accessible abstract provide sufficient evidence?
- If a claim is broader than the source's findings, how should the mismatch be recorded?
- If the source contains relevant information but does not establish the claim, which failure type applies?

You do not have to anticipate every possible situation. Start with the common cases and add rules when your pilot annotations reveal genuine ambiguity.

## Failure types

Here’s a guideline on how to give a failure type

| **Failure type**                 | **Definition**                                                                                       | **Example**                                                                                                |
| -------------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| Missing evidence                 | The source fails to establish the assertion made in the claim.                                       | The claim states that a programme reduced poverty, but the source does not address the effects on poverty. |
| Unsupported number/statistic     | The source fails to establish the numerical value, percentage, count, or measurement asserted.       | The claim reports a 30% reduction in poverty, but the source gives no evidence for that figure.            |
| overstatement / stronger wording | The claim expresses a stronger conclusion or greater certainty than the source supports              | The source says an intervention may improve an outcome while the claim says it guarantees improvement      |
| Unsupported causal link          | The claim asserts that one event caused another, but the source does not establish that relationship | The source reports two events but does not establish that one caused the other.                            |
| contradiction                    | The source explicitly presents information inconsistent with the claim.                              | The claim gives 2015 as the starting year, but the source explicitly identifies 2017.                      |

## Additional rules for edge cases

**Rule 1: **multiple failure types may apply.

If a claim contains both an unsupported statistic and an unsupported causal relationship, record both when the evidence justifies them.

**Rule 2:** Do not assign a failure type if the source is inaccessible or the claim is supported

If a source can not be accessed, leave it blank; if a source fully supports a claim, leave blank.

**How to identify and collect evidence.**

1. Read the source instead of relying on search result snippets.
2. Record the exact excerpts rather than paraphrasing the source in the evidence field.
3. Use multiple excerpts when different parts of the claims are supported by different passages.
4. Distinguish a passage that supports a claim from one that merely discusses the same topic.
5. Do not invent excerpts or read a missing text as evidence
6. Record access limitations honestly.
7. If the source is in accessible, leave blank

**Example:**

**Claim:** A new agricultural programme increased crop yields by 25%.

**Source excerpt:** The programme was introduced in 2020 to improve agricultural productivity.

The excerpt establishes the programme's purpose and introduction year. It does not establish that yields increased by 25%.

The correct question is not whether the programme probably improved yields. It is whether the cited source provides evidence for the specific result claimed.

## How to assess partially supported claims

If a source supports a claim partially, that means some part of the claim is true, and the other wasn’t established by the source

If a source supports one half and contradicts the other, with the other being the crux of the claim, the verdict will be not supported

Example  of a source-claim with a not supported verdict

| **Field **   | **Annotation**                                                                                                                                                                         |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Evidence Excerpts | And the practice is still popular to this day. The ‘Curly Girl Method’ tag on TikTok has more than 1.3 billion views, with people sharing their successes and favorite products to use |
| verdict           | Not supported                                                                                                                                                                          |
| Failure type      | unsupported number/statistics                                                                                                                                                 |
| rationale         | The cited source  supports the method’s continued popularity and high TikTok engagement but provides no evidence of expanded reach or  audience demographics.                          |
